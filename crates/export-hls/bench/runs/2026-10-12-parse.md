# 2026-10-12 parse bench

Measured on this host with `cargo bench` (bench profile: `opt-level = 3`, `lto = "thin"`, `codegen-units = 1`). Clock is `std::time::Instant`. Threading was off. The loopback GET is the local stack on `127.0.0.1`, not a CDN download. No speedup is claimed.

Host: Linux 6.12.94+ x86_64, rustc 1.83.0 (`90b35a6239c3d8bdabc530a6a0816f7ff89a0aaf`).

Fixture: generated media playlist, 1024 `#EXTINF` segments, 55319 bytes, one URI, `#EXT-X-BYTERANGE:9000` every 10000 bytes (1000-byte gap, under the 4096-byte coalesce limit). 20 warmup iterations, then 200 timed iterations. The truncated miss is that playlist cut inside the last `#EXTINF` (`Error::Truncated`).

| 1 | 197638 | 302069 | 187178 | 234441 | HTTP 200, 41 bytes, 1 segment |

Run 1 is the `cargo bench` process. Runs 2 and 3 replay the same release binary. The first p99 is higher than the later runs; that spread is part of the record.

## Local stack two segments from one playlist

Same host and bench profile. One media playlist names two cleartext segments, `http://127.0.0.1:<port>/seg0.ts` and `http://127.0.0.1:<port>/seg1.ts`, 65536 bytes each. `Fetcher::get_segments` fetches both through the cleartext client. One sample covers both fetches. The byte count is their sum, 131072. `check_hop` runs inside that client before each connect. Loopback is allowed only in this bench. The bodies are `text/plain`, not a transcode. One local accept thread sits beside the client. Not a CDN download. The library does not call yt-dlp. `https` stays unsupported.
